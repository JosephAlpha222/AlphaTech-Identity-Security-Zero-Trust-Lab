# AlphaTech-Identity-Security-Zero-Trust-Lab

A practical identity security and Zero Trust laboratory integrating Keycloak OIDC/RBAC with Wazuh SIEM to demonstrate authentication security, authorization, attack detection, correlation, investigation, and incident respon
Project Overview

The project simulates an enterprise identity environment where security events generated by Keycloak are collected by Wazuh, analyzed using custom detection rules, correlated into higher-confidence alerts, and investigated as security incidents.

Security Workflow

Identity → Authentication → Authorization → Attack Simulation → Telemetry → Detection → Correlation → Investigation → Response

Detection Engineering

Custom Wazuh rules were developed to detect identity-related security events:

Rule	Detection	Severity
100100	Invalid OIDC redirect URI	High
100101	Login attempt using nonexistent user	Medium
100102	Five nonexistent-user attempts within 60 seconds	Critical

The correlation rule demonstrates how multiple low-level authentication events can be combined into a higher-confidence brute-force detection.

Attack Scenarios

The laboratory simulated controlled attacks against the identity layer, including:

Invalid OIDC redirect URI attempt
Nonexistent-user authentication attempts
Rapid repeated authentication attempts
RBAC authorization mismatch

These activities generated real Keycloak security events that were ingested and detected by Wazuh.

Incident Response Process

Detected events were investigated using the following workflow:

Validate the alert
Review the originating event
Correlate related events
Determine likely attack behavior
Assess security impact
Define containment/remediation actions
Document the incident
Key Security Findings
Strict OIDC redirect URI validation is essential to protect authentication flows.
Repeated authentication failures become more meaningful when correlated over time.
Identity logs provide valuable telemetry for SOC detection.
RBAC requires consistent mapping between identity-provider roles and application authorization logic.
IAM security should be treated as part of the organization's overall detection and response architecture.
